## In Development

### Amethyst rebuilds its relay authentication decision flow

[Amethyst](https://github.com/vitorpamplona/amethyst) is an Android Nostr client. A block of merged work reshapes how it handles [NIP-42](/en/topics/nip-42/) client-to-relay authentication. The permissions interface and the decision flow were redesigned ([PR #3899](https://github.com/vitorpamplona/amethyst/pull/3899)), authentication now waits for a challenge to resolve instead of timing out ([PR #3905](https://github.com/vitorpamplona/amethyst/pull/3905)), new accounts default to always authenticating with relays ([PR #3931](https://github.com/vitorpamplona/amethyst/pull/3931)), and an "always log in" choice is honored for relays the account does not use itself ([PR #3937](https://github.com/vitorpamplona/amethyst/pull/3937)). Authentication also recognizes [NIP-29](/en/topics/nip-29/) groups and Concord communities as joined venues ([PR #3906](https://github.com/vitorpamplona/amethyst/pull/3906)), which is what stops a relay-hosted group from looking like an unfamiliar relay every time it is opened.

Two other changes touch protocol surfaces. Proof-of-work mining under [NIP-13](/en/topics/nip-13/) refreshes `created_at` while it mines and gains a GPU path analysis ([PR #3911](https://github.com/vitorpamplona/amethyst/pull/3911)), and full-screen napplet hosts handle input-method insets ([PR #3932](https://github.com/vitorpamplona/amethyst/pull/3932)). A guided first-run key backup with a settings entry point also merged ([PR #3909](https://github.com/vitorpamplona/amethyst/pull/3909)), alongside the ability to mute public chats ([PR #3939](https://github.com/vitorpamplona/amethyst/pull/3939)).

### nostrord implements an unmerged encryption-key proposal

[nostrord](https://github.com/nostrord/nostrord) is a Nostr chat client organized around relay-scoped groups. It merged an implementation of NIP-4e, an unmerged proposal to decouple message encryption from the identity key that Compass [last described in the 15 July issue](/en/newsletters/2026-07-15-newsletter/). The account announces its own kind `10044` encryption key, holds the private half locally, and decrypts inbound direct messages in process, which takes a bunker or browser extension out of the read path entirely ([PR #261](https://github.com/nostrord/nostrord/pull/261)). Device pairing over kinds `4454` and `4455` moves that key to a second device, and a self-archive republishes history addressed to the new key. Sending was addressed to the announced key first ([PR #247](https://github.com/nostrord/nostrord/pull/247)), and a follow-up fixed pairing that negotiated successfully without handing the key over ([PR #271](https://github.com/nostrord/nostrord/pull/271)). The pull request states that the wire format follows the deployed Jumble implementation where it diverges from the open proposal, which places this specification's working definition in shipped code instead of in the document.

Group identity was tightened in the same batch. A group identifier is now unique only within its relay ([PR #269](https://github.com/nostrord/nostrord/pull/269)), so the same identifier on two relays is treated as two groups ([PR #272](https://github.com/nostrord/nostrord/pull/272)), and thread posts render as forum posts ([PR #274](https://github.com/nostrord/nostrord/pull/274)). Connection churn that produced repeated kind `22242` signing prompts was also stopped ([PR #268](https://github.com/nostrord/nostrord/pull/268)), which is the same class of signer pressure Cambium spent three releases on this week.

### nostream adds a relay monitor and mints invite codes

[nostream](https://github.com/cameri/nostream) is a TypeScript relay implementation. It merged a cluster worker and probe scheduler that publish [NIP-66](/en/topics/nip-66/) relay monitoring events, the discovery specification that lets a monitor announce liveness and capability data about other relays ([PR #724](https://github.com/cameri/nostream/pull/724)), with a settings schema and defaults ([PR #689](https://github.com/cameri/nostream/pull/689)) and integration tests ([PR #733](https://github.com/cameri/nostream/pull/733)). A command-line tool now mints [NIP-43](/en/topics/nip-43/) invite codes, the relay access metadata scheme that gates admission ([PR #732](https://github.com/cameri/nostream/pull/732)), and the relay finally advertises [NIP-13](/en/topics/nip-13/) proof of work in its supported list ([PR #680](https://github.com/cameri/nostream/pull/680)), which it had implemented without announcing. Data vending machine jobs also gained a persistence migration and repository ([PR #727](https://github.com/cameri/nostream/pull/727)), and the relay now traps [NIP-90](/en/topics/nip-90/) (data-vending-machine job requests) and records them through the job repository ([PR #729](https://github.com/cameri/nostream/pull/729)).

### rust-nostr fixes a gift-wrap identifier and rejects protected reposts

[rust-nostr](https://github.com/nostrdevkit/nostr) is the Rust library and software development kit behind a large share of the Rust and mobile client work in this issue. It now ensures the rumor identifier is computed before the gift-wrap seal is encrypted ([PR #1444](https://github.com/nostrdevkit/nostr/pull/1444)), the same class of defect Mostro fixed in its own library this week. Its local relay rejects a repost of a [NIP-70](/en/topics/nip-70/) protected event ([PR #1445](https://github.com/nostrdevkit/nostr/pull/1445)), which is the protection that specification exists to provide, and NIP-47 response parsing tolerates missing and null amounts ([PR #1450](https://github.com/nostrdevkit/nostr/pull/1450)) instead of failing on a wallet that omits them. Relay URL parsing was hardened ([PR #1451](https://github.com/nostrdevkit/nostr/pull/1451)).

### NDK adds post-quantum direct messages and drops a GPL dependency

[NDK](https://github.com/relaystr/ndk) is a Dart development kit for Nostr. It merged hybrid post-quantum encryption for direct messages using ML-KEM-1024, the lattice key-encapsulation mechanism standardized as FIPS 203 ([PR #713](https://github.com/relaystr/ndk/pull/713)), placing it alongside the classical key agreement instead of in place of it. A separate change replaced a GPL-3.0-only Dilithium implementation with `fips204`, the ML-DSA signature standard ([PR #712](https://github.com/relaystr/ndk/pull/712)), which removes a licensing constraint for applications embedding the kit. Connections also moved to one identity each ([PR #710](https://github.com/relaystr/ndk/pull/710)).

### Nostter adds bookmark lists, profile badges, and Blossom uploads

[Nostter](https://github.com/SnowCait/nostter) is a web client. It merged support for both the standard and the legacy shapes of [NIP-51](/en/topics/nip-51/) bookmark lists ([PR #2311](https://github.com/SnowCait/nostter/pull/2311)), updated its handling of NIP-58 profile badges ([PR #2281](https://github.com/SnowCait/nostter/pull/2281)), added a Blossom media uploader ([PR #2298](https://github.com/SnowCait/nostter/pull/2298)), and now shows a [NIP-05](/en/topics/nip-05/) identifier, the DNS-based verification name, in the mention autocomplete ([PR #2303](https://github.com/SnowCait/nostter/pull/2303)).

### Zap Cooking binds admin routes to signed requests and encrypts stored wallet connections

[Zap Cooking](https://github.com/zapcooking/frontend) is a recipe site built on Nostr long-form events. A security batch encrypts stored Nostr Wallet Connect connection strings at rest inside a NIP-44 envelope ([PR #622](https://github.com/zapcooking/frontend/pull/622)), replaces a spoofable public-key comparison on administrative routes with [NIP-98](/en/topics/nip-98/) HTTP authentication, the scheme that signs an event to authorize an HTTP request ([PR #626](https://github.com/zapcooking/frontend/pull/626)), and clears account data on logout while bounding pending NIP-46 records ([PR #627](https://github.com/zapcooking/frontend/pull/627)).
