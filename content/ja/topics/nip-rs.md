**ステータス:** これは Buzz プロジェクト固有のドラフト提案です。NIP-RS は正式に採用された NIP ではありません。この名称は Buzz プロジェクトのドキュメントに由来するもので、公式の NIPs リポジトリが割り当てたり承認したりしたものではありません。

## 目的

NIP-RS を使うと、1 人のユーザーが持つ複数のデバイスの間で、そのユーザーがどこまで読んだかを共有できます。各インストールは `kind:30078` の addressable event を公開します。その `d` tag は `read-state:` の後にランダムなスロット ID を続けたもので、content はユーザー自身の鍵宛てに NIP-44 で暗号化されます。平文はコンテキスト ID をタイムスタンプのフロンティアに対応付けており、各フロンティアは、その時刻以前のものがすべて既読であることを意味します。このドラフトは既読通知を公開せず、他の人が何を読んだかも明かしません。

## 制限

フロンティアは、最近のアクティビティに関するベストエフォートのヒントです。既読メッセージの完全な履歴を構成するものではありません。手動で未読に戻す上書き（tombstone フロアを含む）は、別個の永続的な取り決めに従います。上書き状態の全体を読み込めるかどうかは、クライアントが完全には検証できない relay の順序付けや容量に関する挙動に左右されるため、任意の relay が完全な未読状態を返すとは限りません。コンテキスト ID は、ほとんどの場合、1 つのクライアントファミリーの中でしか意味を持ちません。

オープン中のプルリクエスト #8639 は、Buzz クライアントを、デフォルトで無効化された非公開の認証付き HTTP API を基盤とする `buzz_v1` NIP-11 機能へ移行することを提案しています。この機能を持たない relay では、引き続き NIP-RS が使われます。
